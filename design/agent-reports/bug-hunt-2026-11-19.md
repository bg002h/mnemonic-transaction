**Audit date** 2026-11-19, America/Phoenix. **Revision** `61c66a4648421939af293d00d866464cca8d871d` (`main`, mt-cli and mt-codec 0.2.0). The starting checkout was clean. Author: OpenAI Codex, GPT-6. **Proposed severity totals** COUNT_PLACEHOLDER.

## Critical

### C1 · An RPC error becomes a verdict that the engraving is scrap

**New.** `crates/mt-cli/src/node.rs:66,99`, `report.rs:199,234`, `main.rs:585`. Entry points are `inspect`, reporting in `decode`, and the spent-input guard in `encode`. `Node::call` discards the RPC failure. `txout` converts both failure and an unparsable value into the same state as a successful empty result. A confirmed parent then supplies the other half of a false DEAD verdict.

**Reproduction.** On an isolated regtest node with txindex synced, fund a wallet and finalize a spend of a confirmed UTXO. Leave it unbroadcast. Inspect the raw hex using a `--bitcoin-cli` wrapper that forwards the method and arguments supplied on stdin. Control: `LIVE — every input unspent`. Make the wrapper exit 1 only for `gettxout`, forwarding every other call unchanged. The same inspection exits **0** with `DEAD — an input was spent by someone else. The engraving is scrap`. Core's `testmempoolaccept` on those exact bytes returned `allowed: true`. A deterministic stub variant also made `encode` exit 1 and tell the operator the transaction could never be broadcast. Expected: an unavailable observation and no advice to discard or replace the engraving.

**Fix and regression.** Preserve RPC success, valid null, and failure as distinct results. Give unavailable and malformed replies an indeterminate status and skip the definitive spent-input refusal for them. Likewise distinguish a failed parent lookup from a genuine not-found response before using a synced txindex to infer PENDING. Extend `tests/common/mod.rs::node_stub` with per-method exit status. Exercise error + confirmed parent, valid unspent + confirmed parent, and successful null + confirmed parent; the last case still gives DEAD when the transaction itself has not confirmed. Pin the holder-facing text as well as JSON.

### C2 · Failed artifact and report writes return success

**New.** `crates/mt-cli/src/main.rs:880,889,1334,1344,1391,1409,1576,1691` (encode emission, decode output, verify verdict, and both inspect report writers). All four verbs discard I/O errors on their result streams. A caller can mark a backup job complete with no artifact.

**Reproduction.** In the fixture directory open a new private regular file in binary write mode and call `invoke(["encode","--bitcoin-cli","/nonexistent","--in","final.b64"], 0, file)`. Exit **0**, file **0 bytes**. The unrestricted control writes **796 bytes**. Analogous `decode --in even.txt` and `inspect --in even.txt` both returned 0 with empty files. The decode control produces **445 bytes**. Swapping the limited file to stderr also produced exit 0 with no verify verdict or, for `decode --json`, the hex on stdout but no requested JSON report.

**Fix and regression.** Return and propagate write and final flush errors on each promised result channel. A failed stderr cannot carry its own diagnostic, but the exit status can still indicate failure. Exercise each verb, both encode formats and both decode report modes against a failing regular file. Include a writer that fails only on flush. Keep the public-vector success controls byte-exact.

### C3 · A failed named-file replacement destroys the previous backup

**New.** `crates/mt-cli/src/main.rs:848–862`, `mt encode --out PATH`. Pinned `mnemonic-io-lib` revision `6c24e628`, `crates/mnemonic-io-lib/src/write.rs:45,49,64` opens with truncate before writing.

**Reproduction.** `m encode --in final.b64 --out backup` creates a valid 796-byte file. Call `invoke(["encode","--bitcoin-cli","/nonexistent","--in","final.b64","--out","backup"], 8)`. Exit **1**, old backup replaced by an **8-byte prefix**. The diagnostic says “nothing was left behind.” Expected: the original still verifies after the failed replacement.

**Fix and regression.** For regular-file replacement, write completely to a private temporary file in the destination directory, check completion, then atomically replace the destination. Clean up a failed temporary file and make the diagnostic describe the actual outcome. Cover fresh, shorter successful, failed replacement and alias cases (I4), retaining private permissions. Make any shared-writer change at its owner and update the pin here.

## Important

### I1 · Trailing raw transaction bytes are silently dropped on creation and accepted on recovery

**Prior lead, now reproduced in both directions.** `crates/mt-cli/src/main.rs:949–952,2102–2105`; `encode`, `inspect`, `verify --transaction` and content-ID checking on the recovery verbs parse one transaction from a cursor without requiring EOF.

**Reproduction.** `cat raw.hex even.hex | m encode --qr` exits 0 and emits the first transaction's 682-byte record. Reverse the two files and the result is the other transaction's 448-byte record. Each matches its respective standalone control. For recovery, call `mt_codec::encode` on the public `even` transaction bytes with one `0xab` byte appended, keeping its original display txid. `verify --transaction even.hex` reports OK and a full-txid match. `decode` emits **447** characters including newline, ending in `ab`; the control emits **445**. The ID check consumed fewer bytes than the recovery output.

**Fix and regression.** Use full-slice consensus deserialization in both helpers, with verb-appropriate diagnostics. Test two distinct concatenated transactions in both orders, a one-byte suffix on the comparison file, and the suffix-bearing card set. Require nonzero status and no recovered artifact. Retain the specified full-txid comparison for two independently well-formed transactions.

### I2 · Binary and base64 PSBT intake silently accepts another record after the first

**Prior lead for lenient base64; binary framing also reproduced.** `crates/mt-cli/src/input.rs:50–56,254–272` and `main.rs:428,1447,1540`. The private base64 decoder stops at the first `=`. The pinned `Psbt::deserialize` also returns after reading the declared maps without requiring the input slice to end.

**Reproduction.** `cat final.psbt final.psbt | m encode --qr` and `cat final.b64 final.b64 | m encode --qr` both exit 0 and emit the original 682-byte record. A finalized legacy PSBT appended to the base64 fixture likewise disappears. Appending `=oops` to the base64 text still succeeds. The standalone binary and base64 controls produce identical output. An extra record or non-whitespace suffix should stop a single-input command.

**Fix and regression.** Validate the entire normalized base64 spelling, including padding, and parse PSBT maps through a cursor with an explicit EOF check. Use the same helper in encode, inspect and verify comparison-file intake. Test binary concatenation, padded base64 followed by a second record, junk after padding, and a valid line-wrapped export.

### I3 · Inspect reports the unsigned template's txid and loses fee records from a finalized PSBT

**New.** `crates/mt-cli/src/main.rs:1538–1560`, `mt inspect --in finalized.b64`. It selects `psbt.unsigned_tx` and supplies no UTXO values to the report. For legacy inputs that identifies a different transaction. It can consequently query the node for the wrong spend.

**Reproduction.** Use the public helper `crates/mt-cli/tests/legacy.rs::legacy_psbt(true, None)`. On exactly the same base64 fixture offline, `encode` reports txid `f53f470198d74046a49f3e7584bef4274657d8f3ce98df29af9c411a4d19ec7b` and fee `0.00100000 BTC`, input `TXID-BOUND`. `inspect` exits 0 and reports `015cfdd32127b80169a9c8fb51c578c6b39f4a1c119d51457f76d630443ac304` and fee UNKNOWN. On the ordinary P5 PSBT, the native SegWit txids agree but inspect still drops the input values.

**Fix and regression.** Report the extracted transaction for finalized PSBTs, and carry the validated UTXO values with their actual provenance. If inspecting an unfinished PSBT is supported, label the template explicitly. Adapt the no-node warning to the values already known. Compare inspect, encode and the separately serialized extracted legacy transaction; assert the txid, amount, provenance and fee, offline and in JSON.

### I4 · Encoding to the input path silently overwrites the source PSBT

**New.** `crates/mt-cli/src/main.rs:366–382,832–848`, `mt encode --in FILE --out FILE`. The source is read in full before the destination is opened. Successful conversion can destroy wallet metadata that the card format does not preserve.

**Reproduction.** `cp final.b64 source; m encode --in source --out source` exits 0. The former PSBT now starts with `mt1pgej7`. The same happened when source and destination were two hard links to one file. A distinct destination works and leaves the PSBT intact.

**Fix and regression.** Before touching an existing destination, compare source and destination file identities, including aliases, and refuse the collision. Also consider a regular file redirected into stdin with that same file passed as `--out`. Test identical paths and hard-link aliases, checking original content and mode, plus a distinct-file control. Atomic replacement alone still loses the source at the identical pathname.

### I5 · Inspect rejects a supported binary PSBT before sniffing it

**New.** `crates/mt-cli/src/main.rs:976,1024,1643–1648`, `mt inspect`. `m inspect --json --in final.psbt` exits 1 with “input is not text” and no report. `m inspect --json --in final.b64` exits 0; `encode` accepts both encodings of the same bytes. Every binary PSBT contains the non-UTF-8 magic byte `ff`.

**Fix and regression.** Keep the original bytes until inspecting the magic and selecting a subject. Apply text conversion only to text subjects and preserve binary bytes before whitespace processing. Send both forms through stdin and `--in`, requiring equal JSON for the same finalized transaction.

### I6 · Inspect misroutes legal grouped or recoverable plate input

**New.** `crates/mt-cli/src/main.rs:1525,1647`, `mt inspect`. Routing checks the literal start of the whole input before the string reader can undo grouping, restore an elided prefix or repair the separator.

**Reproduction.** `m encode --in final.b64 --group-size 2 > grouped; m inspect --in grouped` refuses, calls the input encode's own output and recommends `mt inspect` again. `m verify --in grouped` succeeds. Group size 1 has the same problem. On the public `even` set, replacing the first `mt1` with `mtl`, or eliding the first line's 11-character prefix while leaving a full line later, also succeeds in verify and fails in inspect. Ordinary complete lines inspect successfully.

**Fix and regression.** Recognize actual raw-transaction/PSBT subjects and allow recoverable string syntax through the same reader used by decode and verify. Test all three forms against the clean transaction's txid; keep raw, PSBT and genuine foreign-input diagnostic controls.

### I7 · A repaired full plate's mistyped prefix is copied onto undamaged plates

**New recovery failure, related to the filed display defect I8.** `crates/mt-cli/src/read_strings.rs:556–558,608,632–639`, `decode`, `verify` and plate inspection. Prefix restoration copies the typed characters before applying BCH. Damage on one plate consumes correction capacity on other plates.

**Reproduction.** Start with `even.strings_elided`. On the first full line, substitute each symbol at zero-based offsets 3, 4, 5 and 6 with `p` (use `q` when it was already `p`). On the second, elided line substitute offset 20 the same way. `verify` refuses string 2, saying more than four characters differ. Only **one** character on that plate differs. Restoring the first line to the fixture makes the set verify. Each physical plate is within its four-substitution budget.

**Fix and regression.** Decode a usable full plate first, derive the canonical prefix from its corrected header, and use it to expand elided lines. Handle conflicting prefix sources explicitly. Assert exact recovered bytes and correction counts of four and one, including when the sole full line comes later.

### I8 · The successful recovery report gives the holder a prefix absent from the clean set

### I9 · An accepted grouping separator produces an unreadable backup

**New variant of the earlier non-whitespace separator defect.** `crates/mt-cli/src/main.rs:930–937,2171–2174` and `read_strings.rs:62–65`. `m encode --in final.b64 --group-size 5 --separator $'\n' > grouped` exits 0. ### I11 · Decode and inspect accept a comparison that they never perform

### I12 · Asking for stdin and a file silently selects the file

**New.** `crates/mt-cli/src/main.rs:67–82,240–251,370,991–1006`, all four verbs' positional `-` and `--in`. `m decode --in other.txt - < even.txt` exits 0 with the **569-byte uneven** result and no source-conflict notice. **Fix and regression.** Reject an explicit positional dash with `--in` before opening either source. Distinguish implicit default stdin from a requested source when handling admitted argv material as well. Use two different public vectors as the assertion oracle and test ordinary piped stdin, lone dash and lone file.

### I13 · The node's JSON formatting changes a parent from pending to confirmed

**Prior lead.** `crates/mt-cli/src/node.rs:178–191`, liveness reporting and encode's spent-input refusal. With a reachable stub, successful empty `gettxout`, the inspected tx absent, and parent lookup returning `{"confirmations":  0}` (two spaces), `inspect --json` exits 0 with `Dead`. The method looks for two particular spellings of zero. A confirmed parent with integer 1 and a spent output is the real DEAD control.

**Fix and regression.** Parse the top-level field and compare its integer value with one; classify a successful mempool response appropriately and an unrecognized reply as indeterminate. Run equivalent zero-valued JSON with zero, one and two spaces and with a newline. Require PENDING for all, and preserve the positive-confirmation control. This remains necessary after C1, since this RPC succeeded.

### I15 · Valid scientific notation changes a chain-fetched input value by 100 million times

**New.** `crates/mt-cli/src/node.rs:99–103,203–213`. `inspect --json --in raw.hex` against a `--bitcoin-cli` wrapper returning `{"value":5e-8}` for each `gettxout` emits **500,000,000 verified satoshis per input**. ### I18 · The public codec returns different bytes when the same chunks are reordered

**Prior lead, now shown to lose data.** `crates/mt-codec/src/string_layer/pipeline.rs:203–218,278–290,351–356`, `mt_codec::decode` and `pipeline::decode_chunk`. The first supplied non-final chunk determines how many bytes to take from every other non-final chunk. Neither the header count nor the checksum certifies this geometry.

**Minimal library reproduction.** Build three valid codewords with one set ID, count 3, indices 0/1/2 and payloads `[1,2]`, `[3,4,5]`, `[6]`. For each, concatenate `ChunkHeader::new(0x12345,3,index)?.to_symbols()` and `bch::bytes_to_5bit(payload)` and pass them to `bch::encode_5bit_to_string`. Decode in order 0,1,2: `Ok([1,2,3,4,6])`. In order 1,0,2: `Ok([1,2,3,4,5,6])` (values shown are `DecodedSet.bytes`). The separately exposed plan override also silently turns the first 37-byte `even` chunk into `[2,0]` given `Some(Chunking { count:6, bytes_per_chunk:2, last_chunk_bytes:37 })`.

**Fix and regression.** Determine canonical geometry from the complete distinct chunks and `chunk::plan(total_bytes)`. Enforce count, non-final lengths, final length and the 40-byte ceiling. Reject an inconsistent explicit plan before returning data. Concatenate validated payloads in header order without truncation. Every permutation of the malformed set should return an error. Shuffled full-size boundary controls and the two independent vectors must return their original bytes.

### I19 · Nonzero padding passes the codec and CLI verification

**Prior lead.** `crates/mt-codec/src/string_layer/pipeline.rs:199–218`, `decode_chunk`, `decode` and all plate-reading CLI verbs. The implementation drops residual bits instead of checking the canonical zero padding required by the byte-to-symbol representation.

**Reproduction.** Take `bch::decode_string(&even.strings[0])?.data().to_vec()`, XOR its final symbol with 1 and re-encode those symbols with `bch::encode_5bit_to_string`. Replace only that plate in `even.txt`. The public `bch::five_bit_to_bytes(&symbols[11..])` rejects the modified body. `mt_codec::decode` nevertheless returns exactly the original 222 bytes and `mt verify` reports OK without correction. The unchanged set passes both paths.

**Fix and regression.** Use the existing checked byte conversion after header removal and BCH correction; report malformed/excess padding as an invalid chunk. Test nonzero pad bits, an extra all-zero symbol when that would be excessive, and canonical non-byte-aligned bodies. The permissive loop is in mt's transaction pipeline, outside the shared BCH mathematics.

### I20 · A valid PSBT global key can make its base64 export unrecognizable

**New.** `crates/mt-cli/src/input.rs:31–32,50–56`, encode and verify comparison input, and base64 PSBT inspection. `cHNidP8` includes bits from the byte **after** the five-byte magic. A different first map-key length can change the last prefix character.

Preserve the named truncated-PSBT diagnostic. Test both representations of a PSBT whose first key length has nonzero high bits, alongside the ordinary vector. Keep the raw-argv classifier in `validate.rs:663` consistent with valid PSBT spellings.

### I21 · The engraving instructions count prefix characters that elided output omits

**Filed.** `R-fold-adversarial-round2.md` finding 5. `crates/mt-cli/src/main.rs:724–730,753–766,919–939`, `encode --elide-prefix`. `m encode --in final.b64 --elide-prefix > cut` reports “9 strings, **787** characters” and says all nine start with `mt1pgej7qqg`. ### I24 · A valid Unix path can panic the CLI before it opens the file

### I25 · The documented live smoke test fails under an ordinary umask

## Minor and Nit

### M1 · The public encoder accepts strings that cannot be display txids

**Prior lead.** `crates/mt-codec/src/string_layer/pipeline.rs:23–27,53–55`, `content_id_from_txid_display` and `mt_codec::encode`. ### M2 · The public five-bit encoder panics on a bad symbol

**New.** `crates/mt-codec/src/string_layer/bch.rs:545,574–575`, `bch::encode_5bit_to_string(&[32])`. It advertises a `Result` but indexes the 32-entry alphabet and panics at index 32. Values 0–31 are its intended domain; this is a library caller error, outside ordinary CLI input. Reject out-of-range symbols before checksum calculation and array indexing; test 31, 32 and 255. The existing checked byte-conversion API already refuses out-of-range symbols.

Per the BCH-port rule I checked both siblings. A scratch client linked to the cached mk-codec from the mnemonic-key checkout (`95d70a5`) reproduced the panic at `crates/mk-codec/src/string_layer/bch.rs:564`. The md checkout (`62280dd9`) uses a different private `crates/md-codec/src/chunk.rs:548–552` renderer with masked indexing. No matching public encoder/panic was found there; this was a source comparison for md.

### M3 · A mixed-provenance fee report says no input was verified

**New.** `crates/mt-cli/src/report.rs:272–285,376–382`, encode's prose report. ### M4 · The refusal misdescribes what an ALL|ANYONECANPAY signature commits to

**New.** `crates/mt-cli/src/validate.rs:1353–1368,1374–1383`, `encode`. Change the first witness signature's trailing sighash marker in P5 raw bytes from 1 to `0x81` (offset 193 on this fixture). The expected policy refusal occurs, but it says `SIGHASH_ALL|ANYONECANPAY leaves this transaction's outputs UNBOUND` and that a holder can redirect them. ALL still commits to all outputs; ANYONECANPAY changes input coverage. The pinned bitcoin crate's `crypto/sighash.rs::segwit_v0_encode_signing_data_to` includes the output digest for this base type. Preserve the refusal, describe the actual commitment for each supported flag, and use a neutral explanation for unknown flags. Assert 0x81 receives its correct reason and `sighash_none_raw_hex` still receives the unbound-output explanation.

### M5 · Ineffective grouping options give inconsistent results

### M8 · The shell-history test suite can spend its deadline in machine-wide startup hooks
